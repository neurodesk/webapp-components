# synthsr

Self-contained native SynthSR v2 executable. The checksum-pinned
`synthsr-v2.onnx` model is embedded and ONNX Runtime is statically linked, so it
runs offline with no FreeSurfer, Python, Node.js or browser. macOS Apple Silicon
is the supported release; the source builds anywhere the `ort` crate does.

```sh
synthsr input.nii.gz                 # writes input_synthsr.nii.gz + input_synthsr.json
synthsr ct.nii.gz out.nii.gz --ct    # CT in Hounsfield units
synthsr --self-check                 # build target, model hash, ONNX Runtime version
```

Defaults match `mri_synthsr --i IN --o OUT --cpu`: v2 general model, left–right
flip averaging, unsharp masking, 1 mm isotropic uint8 output. `--no-flip`,
`--no-sharpen`, `--threads N` (default: all cores, or `SLURM_CPUS_PER_TASK`),
`--force` to replace existing output, `--quiet`.

`--device` selects the backend; each one runs the whole graph or fails, never a
silent partial fallback:

| Device | What runs | M4 Pro, 192×256×192, both passes |
| --- | --- | --- |
| `metal` (macOS default) | Native Metal port of the webapp's blocked FP32 Conv3D kernels ([src/metal.rs](src/metal.rs)) | 4-5 s, 0.45 GB |
| `cpu` (default elsewhere) | ONNX Runtime CPU provider, all cores | 10-11 s, 8 GB |
| `webgpu` | ONNX Runtime WebGPU provider (Dawn on Metal) | 43-52 s, 0.4 GB |

`metal` requires Apple Silicon, macOS 13.4+ and a real Metal device; without a
GPU (a VM, headless CI) it fails with "No Metal device is available; use
--device cpu." `--self-check` probes each device in a child process
(`--probe DEVICE` is the internal helper), so a crashing provider can't take
the report down with it; exit status depends only on the CPU probe.

Backends are the `Net` enum and `DEVICES` list in `main.rs`; CUDA and others
slot in as new variants. Linux, Windows, CoreML and x86_64 builds are
deferred. 4D, non-finite and constant images are rejected. Output is never
written over the input.

The JSON sidecar records settings, input/output geometry, model SHA-256,
executable SHA-256, ONNX Runtime version, execution provider, host target and
per-phase timings. It is field-compatible with the Node CLI in
`packages/synthsr`.

Synthetic images can alter or fill lesions; keep the original scan for
interpretation. No skull stripping or spatial normalization is performed.

## Install (macOS)

Download `synthsr-VERSION-macos-arm64.pkg` and open it. The package is
signed with a Developer ID, notarized by Apple and stapled; it installs
`/usr/local/bin/synthsr` and `/usr/local/lib/synthsr/libwebgpu_dawn.dylib`
(the WebGPU runtime, loaded only for `--device webgpu`). Requires macOS 13.4 or
later on Apple Silicon.

## Build

```sh
make check-model   # fetches the revision-pinned ONNX from Hugging Face into models/, verifies SHA-256
make build         # target/release/synthsr (build.rs re-verifies the model before embedding)
make test          # fixture parity and CLI tests on every device whose probe succeeds (cpu required)
make lint fmt
```

Requires current stable Rust. The first build downloads pyke's static ONNX Runtime
binaries for the host target (checksum-pinned in `ort-sys`).

The model is `synthsr/models/synthsr-v2.onnx` in the Hugging Face dataset
`neurodeskorg/webapps`, pinned by commit in
`packages/synthsr/model.manifest.json`; the same dataset holds the upstream
checkpoint `synthsr_v20_230130.h5` for provenance. It is never committed here.
`scripts/repoint_model_manifest.sh COMMIT` repins both model manifests to a
new revision.

## Validation

`make test` checks the synthetic fixtures against the pinned Python contract.
`make test-real` (the `#[ignore]`d `real_volumes` test) reads goldens listed in
`$SYNTHSR_REFERENCE_DIR/manifest.jsonl`, generated by
`scripts/generate_reference.sh` (Node CLI and FreeSurfer 8.1.0
`mri_synthsr --cpu`), and writes `$SYNTHSR_REFERENCE_DIR/report.json`. Gates:
identical shape, affine within 4e-6 mm, max uint8 error 1, mismatched voxels ≤
0.1 % (the tolerance the JS suites use). The last run is in
`validation/report.json` (Apple M4 Pro, ORT 1.28.0): every fixture and all
four T1/MNI volumes pass on all three devices, with at most 549 of 7.2 M
voxels differing by one grey level from FreeSurfer. Metal takes 4–5 s per
volume, CPU 10–11 s, WebGPU 43–52 s; FreeSurfer's own TensorFlow CPU path took
13–16 s on the same machine. This is engineering parity on named hardware, not
clinical validation.

The benchmark volumes themselves live outside the repository
(`$SYNTHSR_REFERENCE_DIR`); moving them into the Hugging Face dataset under
`synthsr/validation/` is planned but blocked on their licensing.

## Release (macOS)

```sh
make macos-notary-profile APPLE_ID='you@example.com' TEAM_ID='ABCDE12345'   # once; password prompted, stored in Keychain
make macos-release VERSION=0.2.20260909   # identities default to the Developer ID certificates in your Keychain
```

`MACOS_SIGN_IDENTITY` / `MACOS_INSTALLER_IDENTITY` default to the first
Developer ID Application / Installer certificate in the Keychain;
`NOTARY_PROFILE` defaults to `synthsr-notary`. `macos-release` checks the
notary profile (`xcrun notarytool history`), runs the tests, signs the Dawn
dylib and the executable (hardened runtime, timestamp), builds and signs the
`.pkg`, submits it with `notarytool --wait`, staples, validates, expands the
package to re-verify signature/dependencies/execution, and runs `spctl
--assess --type install`; the combined output is recorded in
`dist/<pkg>.validation.txt` beside the `.pkg` and its `.sha256`.
`make macos-pkg-adhoc` writes `dist/synthsr-VERSION-macos-arm64-adhoc.pkg`
(never the release name) for local testing. No secret is passed as a Make
variable.
