# dwi2trx

Browser-only diffusion-MRI pipeline: load a DWI (NIfTI + bval/bvec, or a DICOM
folder), optionally brain-extract the b0 with MindGrab (WebGPU), fit the
diffusion tensor with a vendored dtifit-enabled niimath WASM build, track
streamlines on the GPU with `@dipy/gpu-streamlines`, and save a TRX
tractogram. Everything runs client-side; no imaging data leaves the browser.
It also includes a standalone gradient-scheme viewer/generator (bvec/bval
inspection, uniform multi-shell direction generation for Siemens/GE/Philips).

From the repository root:

```bash
npx pnpm@11.7.0 --filter dwi2trx dev
npx pnpm@11.7.0 --filter dwi2trx build
npx pnpm@11.7.0 --filter dwi2trx test
npx pnpm@11.7.0 --filter dwi2trx test:e2e
```

`dev` and `build` first run `scripts/copy-brainchop.mjs` (see below). `test`
runs the Node test suite (`test/*.test.js` plus the TypeScript sources under
`src/`, via `node --experimental-strip-types`). `test:e2e` runs Playwright
against a built-and-served app.

## Requirements

A WebGPU-capable desktop browser (recent Chrome or Edge) — the app throws a
clear error at startup if `nv.attachTo` fails, and streamline tracking
separately requires `subgroups` support (`getTrackingDevice` reports the
specific reason if unavailable). The dev/preview server applies the shared
Neurodesk cross-origin-isolation headers used by the app's Web Workers.
Fitting and tracking a full-resolution DWI is memory-intensive in a
WASM/WebGPU sandbox; see the size limit below.

## Vendored niimath

`vendor/niimath` ships a locally-built niimath WASM with the `--dtifit` CLI
mode enabled (`@niivue/niimath/niimath.js`, driven directly for multi-file FS
staging + `callMain` — see `src/dwi2trx/dtifit.ts`). This is not yet part of
the published `@niivue/niimath` package on npm, so `package.json` pins
`@niivue/niimath` to `file:./vendor/niimath` instead of the registry version.
Do not replace it with the registry package until a dtifit-enabled build
lands upstream. To refresh the vendored build, rebuild niimath's WASM with
`--dtifit` enabled and replace the contents of `vendor/niimath/dist/`; its
`package.json` (license BSD-2-Clause) records the exports.

## public/brainchop

`scripts/copy-brainchop.mjs` copies `@brainchop/mindgrab`'s WebGPU worker,
glue JS, and WASM into `public/brainchop/` before `dev` and `build`. These
files are fetched by URLs computed at run time, so Vite cannot discover and
emit them itself — they must exist as plain static assets under `public/`.
`public/brainchop/` is gitignored and regenerated by every dev/build run.

## Data flow and privacy

Input files (NIfTI/DICOM + bval/bvec) are read and processed entirely in the
browser: DICOM conversion (`@niivue/dcm2niix`), optional brain extraction
(`@brainchop/mindgrab`, WebGPU), tensor fitting (the vendored niimath WASM),
and GPU streamline tracking (`@dipy/gpu-streamlines`) all run locally. Only
the bundled example DWI and the app's own static assets are fetched over the
network; no loaded image, mask, tensor map, or tractogram is uploaded.

## Limitations

- **Input size**: total input is capped at 2 GB (`src/dwi2trx/input-limits.ts`,
  `MAX_INPUT_BYTES`); a converted DICOM series is re-checked against the same
  cap after conversion. This reflects the practical WASM/browser address-space
  ceiling, not a scientific limit — the app shows a dedicated dialog rather
  than a cryptic WASM error.
- **Tensor fit is single b-value / single-shell in practice**: `fitTensor`
  drives niimath's `--dtifit` with one bval/bvec file and no multi-shell
  handling; the gradient-scheme viewer and generator support multi-shell
  acquisitions, but the fit itself does not model them.
- **Unmasked by default**: the fit runs without a brain mask unless MindGrab
  succeeds (`src/dwi2trx/dtifit.ts`) — the b0 is T2-weighted, so an intensity
  mask can wrongly exclude white matter, and the unmasked fit is reported to
  match FSL in-brain.
- **Gradient orientation conventions**: `src/dwi2trx/vectors.ts` and
  `genvectors.ts` treat b-values at or below 50 s/mm² as b0 (no direction),
  snap b-values to the nearest 50 s/mm² to form shells, and keep antipodal
  (+v / −v) directions distinct rather than merging them — a half-sphere
  scheme is meant to look different from a whole-sphere one. The direction
  generator is a heuristic (Winkler simultaneous or Caruyer incremental
  antipodal-electrostatic relaxation), not a certified optimum; treat its
  output as a starting scheme to verify.
- **Tests needing the hosted fixture are skipped without it**:
  `src/dwi2trx/dtifit.test.ts` needs `public/dwi.nii.gz` (+ `.bval`/`.bvec`),
  which is hosted with release data rather than committed; it logs a skip
  message and exits 0 when the fixture is absent.

## Scientific caveats

Not for clinical use. The tensor fit, brain extraction, and tractography are
research tools; verify results (and generated gradient schemes) against your
own pipeline before relying on them.
